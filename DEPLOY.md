# Deploying the Backend to Render

This guide covers deploying the Ebook Reader API backend to Render.com with persistent storage.

## 📋 Prerequisites

- [GitHub](https://github.com) account with your code pushed
- [Render](https://render.com) account (free tier available)
- OpenRouter API key for AI features (get at https://openrouter.ai)

## 🚀 Deploy to Render (using render.yaml)

### Option A: Automatic (recommended)

1. Push your code to GitHub
2. Go to [Render Dashboard → Blueprint](https://dashboard.render.com/blueprint)
3. Connect your GitHub repository
4. Render auto-detects `render.yaml` and shows:
   - **Web Service**: `ebook-reader-api` (Node.js)
   - **Persistent Disk**: 1 GB mounted at `/var/data`
5. Click **"Create All"** and wait for deployment (~5-10 minutes)

### Option B: Manual

1. In Render Dashboard, click **"New" → "Web Service"**
2. Connect your GitHub repo
3. Configure:
   - **Name**: `ebook-reader-api` (or any)
   - **Environment**: Node
   - **Plan**: Free (or paid for better performance)
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Health Check Path**: `/api/health`
4. Click **"Advanced"** → **"Add Disk"**:
   - Name: `data`
   - Mount Path: `/var/data`
   - Size: 1 GB
5. Create the service

## ⚙️ Environment Variables

Set these in the Render dashboard under **Environment** tab:

### Required

| Variable             | Description                                        | Example                        |
| -------------------- | -------------------------------------------------- | ------------------------------ |
| `JWT_SECRET`         | Secret for signing JWTs (auto-generated by Render) | `render-generates-this`        |
| `JWT_REFRESH_SECRET` | Secret for refresh tokens (auto-generated)         |                                |
| `OPENROUTER_API_KEY` | Your OpenRouter API key for AI features            | `sk-or-...`                    |
| `OPENROUTER_MODEL`   | AI model to use                                    | `openai/gpt-4o-mini` (default) |

### Optional (customize as needed)

| Variable                       | Default       | Description                                      |
| ------------------------------ | ------------- | ------------------------------------------------ |
| `JWT_EXPIRES_IN`               | `15m`         | JWT expiration time                              |
| `JWT_REFRESH_EXPIRES_IN`       | `7d`          | Refresh token expiration                         |
| `NODE_ENV`                     | `production`  | Runtime environment                              |
| `LOG_LEVEL`                    | `info`        | Logging level (`debug`, `info`, `warn`, `error`) |
| `ENABLE_REQUEST_LOGGING`       | `false`       | Set to `true` to log all requests to file        |
| `AUTH_RATE_LIMIT_MAX_REQUESTS` | `5`           | Max login attempts per window                    |
| `AUTH_RATE_LIMIT_WINDOW_MS`    | `900000`      | 15 minutes in ms                                 |
| `RATE_LIMIT_MAX_REQUESTS`      | `100`         | General API rate limit                           |
| `MAX_UPLOAD_REQUESTS_PER_HOUR` | `10`          | Max uploads per hour per user                    |
| `AI_RATE_LIMIT_PER_HOUR`       | `20`          | Max AI calls per hour per user                   |
| `ALLOWED_ORIGINS`              | _(see below)_ | Comma-separated allowed CORS origins             |

### CORS Configuration

Set `ALLOWED_ORIGINS` to include your frontend URLs:

**For development:**

```
http://localhost:3000,exp://127.0.0.1:*
```

**For production (Vercel/Expo):**

```
https://your-frontend.vercel.app,https://your-app Expo URL
```

Multiple origins separated by commas (no spaces).

## 🌐 Get Your Backend URL

After deployment, your backend will have a URL like:

```
https://ebook-reader-api.onrender.com
```

The API base URL is: `https://ebook-reader-api.onrender.com/api`

Update your frontend config file (`frontend-app/src/constants/config.ts`):

```typescript
const HOST = "ebook-reader-api.onrender.com"; // your Render URL
const PORT = 443; // HTTPS port
export const BASE_URL = `https://${HOST}/api`;
```

## 📁 Storage & Data

The persistent disk (`/var/data`) stores:

- SQLite database: `library.db`
- Uploaded book files (EPUBs, PDFs)

**Important:** The disk persists across deployments and sleep cycles. Never store data in the temporary filesystem (`/tmp`).

**Backups:** Render does **not** automatically backup the disk. To backup:

1. SSH into your service: `render ssh`
2. Copy `/var/data/library.db` to a safe location
3. Or set up an automated backup script

## 🔍 Verify Deployment

Test the health endpoint:

```bash
curl https://ebook-reader-api.onrender.com/api/health
```

Expected response:

```json
{ "status": "ok", "timestamp": "..." }
```

## 🐛 Troubleshooting

### Database errors

- Ensure the disk is mounted at `/var/data`
- Check `DATABASE_PATH` is set to `/var/data/library.db`
- Delete the service and redeploy if the database is corrupted

### CORS errors

- Add your frontend domain to `ALLOWED_ORIGINS`
- Include `exp://` URLs for Expo Go development
- No spaces between commas

### Upload fails (413/400)

- Check `MAX_FILE_SIZE_MB` env var (default 100MB)
- Ensure `/var/data/uploads` directory exists (created automatically)
- File must be EPUB or PDF

### AI features not working

- Verify `OPENROUTER_API_KEY` is set correctly
- Check logs: `openrouter.ai` should be reachable
- Model name must be valid (e.g., `openai/gpt-4o-mini`)

### Service sleeps (free tier)

- Render free tier sleeps after 15 min inactivity
- First request after sleep takes ~30 seconds (cold start)
- Upgrade to paid plan to keep service always awake

## 📊 Monitoring

- **Logs**: Render Dashboard → your service → Logs
- **Metrics**: CPU, Memory, Requests per second
- **Console**: `render logs` via CLI

## 🔄 Updating

Push changes to GitHub → Render auto-deploys (if auto-deploy enabled). Or manually click "Manual Deploy" in dashboard.

## 🎯 Alternative Hosting Platforms

### Railway.app ($5 free credit)

1. `railway init`
2. Add a Volume (1 GB)
3. Set env vars (same as Render)
4. Deploy

### Fly.io (free tier)

```bash
flyctl launch
flyctl volumes create data --size 1
flyctl secrets set JWT_SECRET=... OPENROUTER_API_KEY=...
flyctl deploy
```

### Self-hosted (VPS)

```bash
git clone <repo>
cd backend
npm install
npm run start
# Use PM2 for process management
pm2 start src/server.js --name ebook-api
```
